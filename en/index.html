00 · The challenge

Same questions, another system, different codes.

Sales leadership wanted for this client what it already had for the first one: sales in units and value, inventory, and the two cross-referenced, by store, category, family, and product. The client exports the data from its retail system, and there the product doesn't come with the manufacturer's barcode. It comes with the GTIN registered by the client or with one of the client's internal codes.

Without translating the code, the sale exists but has no category, family, or name. The dashboard fills up with “unclassified.”

01 · Reuse without copying

The Vitta Dashboard foundation, with the differences in the right place.

Instead of starting from scratch, the project started from the Vitta Dashboard, already proven in production. The rule was clear: keep what is architecture and adapt only what is specific to the client.

KEPT

Everything that is architecture

Fields precomputed on import, cache with prewarming, undo by batch, history, users with roles, password reset by email, and the 7 tabs.

ADAPTED

Everything that is client-specific

Product mapping with the client's code, date parsing for XLSX, SFA code preserved in the filter, separation between daily and monthly data, and a dedicated store mapping.

03 · The code bridge

An intermediate mapping, before any query.

The client's product mapping translates on two keys: first by the client's GTIN and, when there is none, by the internal code. The result automatically feeds the category mapping used by the dashboard, and each sales row comes in already linked to the correct product.

04 · Resilient mapping

Swap the mapping without taking the dashboard down.

Here the mapping changes often: new products arrive, codes get corrected, and mappings get redone. Each swap reclassifies the entire history, and that had to happen without blocking anyone using the dashboard.

BeforeReclassifying the history blocked the dashboard until it finished.
→
AfterReclassification runs in the background, and the dashboard keeps responding.
BeforeUndoing a large mapping exceeded the request timeout.
→
AfterUndo with no timeout, and the reclassification guaranteed to complete.
BeforeAfter swapping the mapping, some tabs showed old categories.
→
AfterAny change to the mapping invalidates the category and aggregate caches.
BeforeMapping imports gave little feedback on what had been accepted.
→
AfterA clear message about what went in, and the original file stored with the batch.
05 · Import

The heavy lifting starts in the browser.

BATCHES

XLSX split in the browser

The spreadsheet is read and sliced in the browser itself before upload. Large files arrive in parts, with a progress bar, without exceeding the server's time limit.

DATES

Excel dates

Dates coming from XLSX got their own parser and always come in with the same format. This also fixed the year filter based on the imported date.

TEMPLATES

Template = last import

The template button downloads the last imported version of each dataset, via stream, ready to edit and upload again.

DAILY × MONTHLY

Each data point at its own grain

Daily sales and monthly data are handled separately, so the sell-out total matches in the comparison with inventory.

06 · Front-end

The same seven tabs, with the client's classification.

The interface inherited the Vitta Dashboard tabs (Vendas Sell Out, Venda Valor, Venda por Dia, Estoque, Sell Out × Estoque, Importar, and Gerenciar Usuários: sell-out units, sales value, daily sales, inventory, sell-out vs. inventory, import, and user management), with filters by year, month, period, store, category, family, and product, and export to Excel and PDF.
